# Удаление собственного загрузчика — дизайн

## Цель

Cyclop перестаёт скачивать файлы по вставленной или перетащенной ссылке. В «Активностях» остаются только завершённые внешние загрузки из выбранной папки, с открытием, показом в Finder и очисткой истории.

## Что удаляется

- поле «Скачать по ссылке», валидация URL и обработка URL-drop;
- `DownloadManager`, `URLSessionDownloadTransport`, собственный источник `downloads.own`, журналы финализации и их UI-действия;
- тесты и локализации, относящиеся только к собственным загрузкам;
- настройки и зависимости, нужные только очереди собственных загрузок.

Перетаскивание файлов в Cyclop по-прежнему добавляет их на «Полку».

## Что сохраняется

- `DownloadsFolderWatcher` следит за выбранной папкой;
- `ExternalDownloadActivitySource` публикует завершённые загрузки браузеров;
- карточка внешней загрузки поддерживает «Открыть», «Показать в Finder» и «Скрыть»;
- настройка папки загрузок и очистка терминальной истории сохраняются.

## Миграция

При старте новая версия один раз отменяет фоновые URLSession-задачи с прежним идентификатором Cyclop, затем удаляет только служебные данные старого загрузчика: `downloads.json` и каталог `DownloadFinalizations` в Application Support/Cyclop. Сами скачанные пользователем файлы не удаляются и не перемещаются.

## Проверка

1. Состав `ActivityComposition` содержит только внешний источник загрузок.
2. Дроп HTTP/HTTPS-ссылки больше не открывает «Активности» и не создаёт загрузку; дроп файлов сохраняется.
3. После миграции служебные файлы удалены, задачи прежней сессии отменены, пользовательские файлы сохранены.
4. Внешняя завершённая загрузка продолжает появляться и удаляется кнопкой очистки истории.
5. Полный `swift test` и сборка бандла проходят.

## Ограничения

- Не меняем CI, не добавляем разрешения и зависимости.
- UI и сообщения остаются на русском.
- Никаких новых средств скачивания файлов в Cyclop.
